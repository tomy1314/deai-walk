# 冲突裁决规则​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​

两个来源的规则合并后，以下场景会冲突。按本文件裁决。

---

## 1. 破折号​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​

- **解释性破折号** → 删，改为逗号、句号或括号
- **对话打断的破折号** → 保留
- **强调性破折号** → 删，靠句式强调

判断：破折号后面是解释/补充 → 删；破折号表示话被打断 → 保留。

---

## 2. 废话/闲笔​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​

- **功能性废话**（“为了实现这一目标”“值得注意的是”）→ 删
- **口语质感废话**（对话中的寒暄、跑题、多余动作）→ 保留，但不超过全文 15%
- **纯填充**（不知道写什么而凑的字）→ 删

判断：删掉后信息完整但少了人味 → 保留；删掉后更干净 → 删。

---

## 3. 三段式​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​

- **强行凑三项**（“创新、灵感、行业洞察”）→ 改为两项或四项
- **事实性三项并列**（“海陆空”“过去、现在、未来”）→ 保留
- **排比三连以上** → 最多两个，第三个必须打破

---

## 4. 第一人称​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​

- **学术/法律/公关** → 不加“我”
- **个人随笔/博客** → 可以加“我”
- **小说第一人称** → 保留，不改为第三人称
- **商业文案** → 视品牌调性，默认不加

---

## 5. 具体化​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​

- 允许：把模糊表述改为具体细节（“一些地方”→“三个城市”）——但前提是原文有依据
- 禁止：添加原文没有的事实、数据、案例
- 禁止：为了具体而编造细节

判断：具体化后的信息能否从原文推出？能 → 允许；不能 → 不添加。

---

## 6. 口语化​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​

- **学术/法律/公关** → 不口语化
- **新闻/商业** → 轻度口语化（删书面腔，不加方言）
- **个人随笔/博客** → 中度口语化
- **小说对话** → 高度口语化
- **小说叙述** → 按作家风格决定

---

## 7. 留白与完整​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​

- **Humanizer-zh 倾向**：删减、具体化、直接陈述
- **novel-generator 倾向**：留白、允许不完整、允许废笔
- **裁决**：
  - 通用文本 → 以 Humanizer-zh 为主，删减优先
  - 小说/叙事文本 → 以 novel-generator 为主，留白优先
  - 分不清文体 → 默认删减优先，但保留一处留白或废笔

---

## 8. 评分与人工判断​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​

- 脚本评分改善但读起来更差 → 以人工判断为准
- 脚本评分未改善但读起来更好 → 以人工判断为准
- 脚本评分和人工判断都改善 → 通过

**评分只作参考，不作门槛。**

---

## 9. 保留项​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​

用户明确要求保留的表达 → 标记为“保留项”，改写时跳过，不因规则冲突而删除。

---

## 10. 脚本失败​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​

Bash 执行失败 → 降级为人工扫描 → 交付时说明“本次未执行自动扫描” → 不假装跑过脚本。

---

## 11. AI 偏爱的高频“文艺词”​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​

- **纯客观生理描述**（如“指尖流出了血”、“桌子上堆着灰”）→ 保留。
- **强行渲染情绪/文艺感**（如“微凉的指尖”、“闷闷的笑了一声”、“铺了一层薄薄的悲伤”）→ 必须替换为具体动作或直接删去。
- **判断标准**：删掉这个词，读者还能感受到画面和情绪吗？能 → 删；不能 → 换成更接地气的词。

## 12. 与创作 skill（百万字小说生成）的冲突裁决
- 创作 skill 的**闸1/闸2/七维硬判定**优先于本 skill 的诊断建议。
- 本 skill 的六层检查表（`narrative_checklist.md`）是**独立诊断/改稿工具**，不参与创作 skill 的每章出稿门槛。
- 创作 skill 的**项目级 banned_words.md** 优先于本 skill 的通用词表。"不由得/缓缓/淡淡/若有所思"等项目级禁词在创作 skill 出稿时零容忍；本 skill 的"二级最多1次"只用于独立诊断。
- 对话占比：创作 skill 8%–55%（guard.py 门槛）优先；本 skill `checklist.md` 维度6 的 5%–65% 改为"诊断参考区间；被创作 skill 调用时以 8%–55% 为准"。
- 本 skill 的**叙述者定位**是改稿前置基线；创作 skill 的**画面感纪律第 6 条**是单章内判定项。一个定基线、一个查越界，不合并。
- 本 skill 的**人格覆盖**（`persona_overlay.md`）被创作 skill 的 `refine.md` 调用时，人格层让位主流程硬项（见 `persona_overlay.md` 冲突裁决表）。
- 去AI味阶段"只砍不加"；创作 skill 精修阶段可加内容；回归校验只修错。三阶段按创作 skill `refine.md` 的顺序锁切换，不混用。
